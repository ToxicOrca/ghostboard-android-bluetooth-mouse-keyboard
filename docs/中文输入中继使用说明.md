# 中文输入中继 · 使用说明

本页说明如何把手机输入框里的内容**原样**送到受控端（尤其是 macOS）。

---

## 一、先看结论：唯一的「原样」方案

蓝牙 HID 是 **Boot Keyboard 协议**，协议层只传 keycode，**没有 Unicode 通道**。
所以"我在手机上打什么，对面就出什么"不能直接实现，必须借一条通道。

| 方案 | 是否原样 | 受控端要求 |
| --- | --- | --- |
| **Unicode·原样直发**（推荐） | ✅ 完全原样 | macOS 输入源切到「Unicode 十六进制输入」 |
| 拼音·逐字 / 整句 | ❌ 不是原样 | 受控端输入法必须是**全拼** |
| 直通·原样按键 | 仅 ASCII | 美式键盘布局 |

**中文用户请直接用「Unicode·原样直发」。**

---

## 二、⚠️ 使用前提：受控端必须开启「Unicode 十六进制输入」

这是**唯一**需要手动配置的一步。不配置的话，中文会变成一堆怪符号。

### macOS

```
系统设置 → 键盘 → 文字输入 → 输入法 → 「编辑…」
  → 左下角 ＋ → 搜「Unicode 十六进制输入」→ 添加 → 勾选
```

然后切换到这个输入源：

- **Caps Lock**，或
- `⌃空格`（Ctrl+空格），或
- 点菜单栏的输入法图标

> 建议顺手勾上 `系统设置 → 键盘 → 文字输入 → 在菜单栏中显示输入法菜单`，
> 这样可以点选，不必依赖快捷键。

### 怎么判断配好了

手机发 `测试`：

| 受控端出现 | 说明 |
| --- | --- |
| `测试` | ✅ 配置正确 |
| `§∂¢∫` 这类怪符号 | ❌ 按键到了，但输入源不是「Unicode 十六进制输入」 |
| 位置错乱的汉字（如 `测试丄`） | ❌ 有 HID 报文被合并，属于程序缺陷，请提 issue |

`§∂¢∫` 不是乱码 —— 它是 macOS 把 `Option`+数字当成普通 Option 组合键打出来的符号。
看到它就说明整条链路是通的，只差输入源没切。

### 代价

「Unicode 十六进制输入」激活时，**Mac 本地打不出中文**。这是预期的取舍 ——
中文由手机提供。该输入源日常打字行为等同美式键盘，不影响英文输入。

## 三、原理（为什么是 4 位十六进制）

macOS 的「Unicode 十六进制输入」会在**松开 Option 的瞬间**插入字符：

```
按住 ⌥ → 敲 4 位十六进制码位 → 松开 ⌥ → 字符上屏
```

所以 `你`（U+4F60）实际发出的按键是：

```
⌥4   ⌥F   ⌥6   ⌥0   →  松开 ⌥  →  「你」
```

该输入法是 **UTF-16BE** 语义，所以 Kotlin 的 `Char` 逐字取码即可；
emoji 等补充平面字符是两个相邻的代理对，天然连续。

### 一个容易踩的坑：相邻报文不能相同

受控端会把**字节完全相同的连续 HID 报文**当成同一次按键，只认一份。
真实键盘每次按键之间必然有抬起报文，所以天然不触发；但程序模拟时必须自己补。

`一` = `U+4E00`，里面有两个连续的 `0`。如果组内只发"按下"不发"抬起"，
第二份报文会被丢弃，少一位十六进制，**之后所有码位全部错位**：

```
期望  6D4B 8BD5 4E00 4E0B   →  测试一下
实际  6D4B 8BD5 4E0|4 + E0B →  测试丄
```

正确做法是组内每个键之后都补发一次"抬起键码、但保持 Option 按住"的报文，
保证**任意两份相邻报文都不相同**。

## 四、中继栏怎么用

| 元素 | 作用 |
| --- | --- |
| 输入框 | 用手机自带输入法输入（搜狗 / 微信输入法 / 系统拼音 / 语音都行） |
| 发送 | 点一下开始发送；发送过程中再点一下中断 |
| 输入框下方 | 实时预演，例如 `→ U+6D4B U+8BD5 (8 键 / 约 0.6 秒)` |
| 模式标签 | 显示当前模式，点击打开中继设置 |
| 长按「发送」 | 打开中继设置（模式 / 粘贴宏目标 / 按键时序） |

### 两个切换键

| 按键 | 实际发送 | 用途 |
| --- | --- | --- |
| `⇪中/英` | Caps Lock | macOS 用它在中/英之间切换 |
| `⌃␣输入法` | Ctrl + 空格 | macOS 切换输入源 |

> macOS **从不使用单独的 Shift** 切换输入法（那是 Windows/Android 的习惯）。

## 五、关于双拼

**「Unicode·原样直发」与双拼/全拼完全无关** —— 全程不经过任何拼音环节，
所以受控端用什么方案都行，发送端（手机）用什么方案也无所谓。

但**拼音模式会受影响**：它发出的是**全拼**（`nihao`）。
如果受控端输入法是**双拼**（小鹤、自然码、微软双拼…），这些字母会被当成双拼码
解析成完全不同的音节，输入法不上屏，屏幕上只剩一串生字母。

遇到这种情况，改用「Unicode·原样直发」即可。

## 六、常见问题

**Q：发送很慢？**
「Unicode 直发」每个汉字要 4 个键（含修饰键保持），节奏是 40ms 按下 / 20ms 抬起 / 组末 60ms。
一个汉字约 0.3 秒，`测试一下`（4 字）约 1.2 秒。这是为了保证不丢码位，属正常。

**Q：能发 emoji 吗？**
能。emoji 是补充平面字符，会被拆成两个相邻的代理对连续敲出。

**Q：能发换行和 Tab 吗？**
能，直接映射到 Enter / Tab，不经过十六进制通道。

**Q：受控端是 Windows 怎么办？**
「Unicode 十六进制输入」是 macOS 特有的。Windows 上没有等价的纯 HID 通道，
只能用「拼音」模式（且受控端输入法必须是全拼），或走剪贴板同步 + `Ctrl+V` 粘贴宏。
